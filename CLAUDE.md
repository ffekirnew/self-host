# self-host

Home server stack run with Docker Compose. Services are exposed through a Cloudflare tunnel (`cloudflared`).

## Layout

Services are grouped by role. Each group has a `compose.yaml`, and each service has its own folder in its group with a `Dockerfile` and a `bootstrap.sh`:

- `compose.yaml` (root): `include:`s every group's `compose.yaml`, plus `cloudflared` and the `proxy` network.
- `downloads/`: `gluetun`, `qbittorrent` (must share a file: `network_mode: service:gluetun`).
- `arr/`: `seerr`, `prowlarr`, `flaresolverr`, `sonarr`, `radarr`, `lidarr`, `bazarr`.
- `media/`: `jellyfin`, `navidrome`.
- `apps/`: `excalidraw`, `tandoor`, `tandoor-db`.
- `monitoring/`: `glance`, `gpu-stats`.

Notes on `include:`:
- Each service is defined in exactly one file. Groups talk over the `proxy` network by container name.
- Relative paths in a group's `compose.yaml` resolve against that group's folder (e.g. `context: ./glance` is `monitoring/glance`).
- `${...}` in group files is interpolated from the root `.env` (the parent project's environment), so includes don't need `env_file`.
- Every group file redeclares the same external `proxy` network. It would merge into the root one anyway; the block keeps each group file accurate on its own (e.g. `docker compose -f media/compose.yaml config`).
- `cloudflared` stays in the root file because it `depends_on` services from every group.

## Prerequisites

- `docker` with the Compose v2 plugin (`docker compose`, not `docker-compose`)
- `make`
- `bash` (for the `bootstrap.sh` scripts)
- `.env` in the repo root with `CLOUDFLARE_TUNNEL_TOKEN`, `NORDVPN_USER`, `NORDVPN_PASSWORD`, `TANDOOR_SECRET_KEY`, `TANDOOR_DB_PASSWORD` (gitignored; never print it). The Tandoor values are generated by `apps/tandoor/bootstrap.sh` if missing.

## Bootstrap

- `./bootstrap.sh` (root) checks the CLI prerequisites, creates the external `proxy` Docker network (the compose files declare it `external: true`, so Compose fails with `network proxy declared as external, but could not be found` without it), then runs `cloudflared/bootstrap.sh` and every `<group>/<service>/bootstrap.sh`.
- `<group>/<service>/bootstrap.sh` creates the host directories that service mounts in its group's `compose.yaml` and checks anything else it needs (e.g. `cloudflared` checks `.env`). When adding or changing a service's volumes, update its `bootstrap.sh` to match. Every service folder has one, even if it does nothing.
- Scripts must be idempotent; `make up` runs bootstrap every time.

## Adding or removing services

- Run `make down` **before** adding a service to or removing one from any `compose.yaml`. If you remove a service from the file while it is still running, Compose no longer manages it, and its container is left behind as an orphan. Make the change, then run `make up`.
- A new service goes in the group that fits its role (folder `<group>/<service>/` plus a block in `<group>/compose.yaml`). A new group needs its own `compose.yaml` (with the `proxy` network block) and an `include:` entry in the root `compose.yaml`.

## Networking

- Services reach each other by container name on the `proxy` network. cloudflared routes public traffic by name, so services don't need host `ports:`. Don't add them unless something on the host needs one, and bind it to `127.0.0.1`.
- `qbittorrent` uses `network_mode: service:gluetun` (NordVPN kill switch). Its ports are published on the `gluetun` service, and other containers reach it at `gluetun:9090`.
- Media pipeline: Seerr → Sonarr/Radarr/Lidarr → qbittorrent (`gluetun:9090`) → `data/torrents/<category>` → hardlinked into `data/media` → Jellyfin/Navidrome. Prowlarr pushes indexers to the arrs; indexers behind Cloudflare need the `flaresolverr` tag.
- Anything that touches downloads *and* the library mounts `~/home-server/data:/data` (one mount, so hardlinks work). Don't split it into separate downloads/media mounts.
- linuxserver images run with `PUID=1000`/`PGID=1000` so files on the host are owned by the user.
- If gluetun can't connect (TLS handshake timeouts, connection resets), suspect a stale server list before blaming the network. Delete `~/home-server/gluetun/servers.json` and re-run `make up` to fetch a fresh one.

## Commands

- `make bootstrap`: run `./bootstrap.sh`
- `make up`: run `bootstrap`, then build if needed and start all services (`docker compose up -d`)
- `make down`: stop services
- `make build`: rebuild images
- `make logs`: follow logs
- `make clean`: stop, **delete volumes**, and remove `jellyfin/data`
